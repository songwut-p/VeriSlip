# สรุปเซสชัน — AI Document Assistant (10 กรกฎาคม 2569)

## เป้าหมายของวันนี้
ทดสอบ OCR กับภาษาอังกฤษและแบบผสมไทย+อังกฤษ (ต่อจากที่ทดสอบไทยล้วนไปแล้วก่อนหน้า) แล้วต่อยอดเป็น structured data extraction

## สิ่งที่ทำเสร็จ

### 1. สร้าง Mock Slip Generator ครบ 3 ภาษา
- `generate_mock_slip_en.py` — สลิปจำลองภาษาอังกฤษล้วน (ฟอนต์ DejaVu Sans)
- `generate_mock_slip_mixed.py` — สลิปจำลองผสม Thai+English (ชื่อธนาคารอังกฤษ, ที่เหลือไทย; ฟอนต์ DejaVu + Waree)
- `generate_mock_slip.py` — เขียนใหม่เป็นเวอร์ชันไทยล้วน ให้ layout ตรงกับอีก 2 แบบเป๊ะ (ขนาดภาพ 600x950, ตำแหน่ง element เดียวกัน) เพื่อเทียบผล OCR แบบ apples-to-apples

ทั้ง 3 ไฟล์ทดสอบรันผ่านเรียบร้อย ไฟล์ png เก็บไว้ที่ `test_files/`

### 2. ทดสอบ Tesseract OCR เปรียบเทียบ 4 config

| ไฟล์ | lang | ผลลัพธ์ |
|---|---|---|
| ไทยล้วน | `tha` | ข้อความไทยถูกหมด แต่ `x` ในเลขบัญชีพังเป็นสัญลักษณ์/เลขไทย |
| อังกฤษล้วน | `eng` | ถูกต้องเกือบ 100% |
| ผสม | `tha+eng` | ดีที่สุดโดยรวม แต่ "10 ก.ค." เพี้ยนเป็น "10 a.m." |
| ผสม | `tha` อย่างเดียว | พังหนักสุด ทั้งชื่อธนาคารอังกฤษและเลขบัญชี |

**ข้อสรุปหลัก:** ภาษาไทยใน OCR ไม่น่าเชื่อถือเท่าภาษาอังกฤษเสมอ ไม่ว่าจะใช้ config ไหน จะมีจุดเปราะบางจุดใดจุดหนึ่งเกิดขึ้นเมื่อมีภาษาไทยเข้ามาเกี่ยวข้อง → ควรใช้ `tha+eng` เป็นค่าเริ่มต้นสำหรับเอกสารผสม/มีอักษรละตินปน แต่ยังต้องมี post-processing ช่วยเสริม

บันทึกผลละเอียดไว้ที่ `ocr_test_summary.md`

### 3. สร้าง `parse_slip.py` — แปลง OCR text ดิบเป็น structured data
- ใช้ `pytesseract` เรียกอ่านภาพโดยตรง (default `lang="tha+eng"`)
- Parse fields: bank_name, amount, currency, sender/recipient name+account, transaction_id, datetime
- **หลักการออกแบบสำคัญ:** field ไหน parse ไม่ได้ จะไม่คืน `None` เงียบๆ แต่บอกเหตุผลชัดเจน (`*_account_issue`, `datetime_parsed.note`) เพื่อให้ error มองเห็นได้เสมอ
- เพิ่มการแปลง พ.ศ. → ค.ศ. และ mapping เดือนไทยย่อ/อังกฤษย่อเป็นเลขเดือน
- แก้บั๊กที่เจอจริงระหว่างทดสอบ: Tesseract แทรกบรรทัดว่างระหว่าง label กับ value ไม่สม่ำเสมอ ทำให้ parser เดิมพลาด → แก้ด้วยการข้ามบรรทัดว่างในช่วงที่กำหนด

### 4. จัดการ Git
- เจอว่า commit แรกมีภาพสลิปจริง (ไม่ใช่ mock) หลงอยู่ → ใช้ `git commit --amend` ลบออกจากประวัติเรียบร้อย (repo เป็น local เท่านั้น ยังไม่ push จึงจัดการง่าย)
- Commit ทั้งหมด 3 ครั้งในวันนี้:

## บทเรียน/ข้อสังเกตสำคัญ
- ตัวอักษรละติน (x/X) ในเอกสารไทยเป็นจุดเปราะบางที่สุดของทุก config ยกเว้นมี `eng` ร่วมด้วย
- คำย่อเดือนไทยที่มีจุดคั่น (ก.ค., ต.ค.) เสี่ยงสับสนกับคำย่อเวลาแบบอังกฤษ (a.m./p.m.) เมื่อใช้ `tha+eng`
- `-l eng` มักแปลง `x` ตัวเล็กเป็น `X` ตัวใหญ่เสมอ
- Debug ด้วย `repr()` ช่วยเผยปัญหาที่ `print()` ปกติมองไม่เห็น (บรรทัดว่างที่ถูกยุบไปตอนแสดงผล)
- ตัดสินใจ (ของผู้ใช้): ควรพัฒนาความแม่นยำของ OCR ให้นิ่งก่อน ค่อยเริ่มทำ RAG chatbot ต่อ เพื่อไม่ให้ debug ยากขึ้นจากการซ้อนปัญหาหลายชั้น

## แผนสำหรับเซสชันถัดไป
1. รวม grayscale + contrast preprocessing เข้ากับ `ocr_image_to_text()` แล้วทดสอบกับ mock slip ทั้ง 3 แบบ
2. ถ้า contrast แบบเดียวกันทั้งภาพยังมี trade-off (ตัวหนา vs ตัวบาง) ให้ลอง zone-based preprocessing
3. สรุปและ lock ค่า default (lang + preprocessing) ของ pipeline
4. การทดสอบกับสลิปจริงเลื่อนออกไปก่อน (สลิปจริงที่ปกปิดข้อมูลแล้วถูกลบทิ้งไปโดยไม่ตั้งใจ) รอมีสลิปใหม่ค่อยกลับมาทำ
5. ส่วน RAG chatbot ยังไม่เริ่ม จนกว่าความแม่นยำของ OCR จะดีขึ้น
